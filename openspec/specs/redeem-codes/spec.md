# redeem-codes Specification

## Purpose
兑换码仅通过 webapp 个人主页使用：登录用户在新 tab 中输入一次性兑换码领取奖励，可查看本人历史；QQ 端 `/兑换码` 指令移除且不留提示桩。同一用户同一码全局仅可兑换一次，占位与奖励写入同事务。

## Requirements

### Requirement: 网页兑换入口
个人主页 SHALL 提供「兑换码」tab：输入框、兑换按钮与行内结果反馈；输入大小写不敏感，服务端按 `XXXX-XXXX-XXXX`（大写字母）格式校验，格式或未知码 MUST NOT 产生数据库写入。

#### Scenario: 登录用户兑换有效码
- **WHEN** 登录用户在 tab 中输入有效兑换码提交
- **THEN** 奖励即时到账，页面展示含奖励说明的成功反馈

#### Scenario: 未登录访问
- **WHEN** 未携带登录凭证调用兑换 API
- **THEN** 沿用全站登录门控返回 401，不执行任何兑换逻辑

### Requirement: 一次性兑换的原子性
同一用户同一兑换码 MUST 仅能兑换一次。占位写入与奖励发放（称号、积分等）SHALL 在同一数据库事务内提交；回调执行失败时整体回滚，占位不复存在，用户可立即重试。

#### Scenario: 重复兑换
- **WHEN** 用户对已使用过的兑换码再次提交
- **THEN** 拒绝并提示已使用，奖励不重复发放

#### Scenario: 奖励写入失败
- **WHEN** 回调写库中途失败
- **THEN** 占位与部分奖励全部回滚，接口返回失败，重试可成功

### Requirement: 本人兑换历史
`/api/me/redeem/history` SHALL 仅返回当前登录用户的兑换记录（码、时间、奖励说明），按时间倒序；迁移前已存在的记录 MUST 原样可见；已从注册表移除的码显示通用占位说明，不泄露旧定义。

#### Scenario: 历史数据兼容
- **WHEN** 用户在迁移前已兑换过某码
- **THEN** 该记录出现在新 tab 的历史列表中

#### Scenario: 越权
- **WHEN** 用户 A 请求历史接口
- **THEN** 仅返回 A 的记录，不含其他用户数据

### Requirement: QQ 指令移除
`/兑换码`、`/兌換碼` MUST 不再被任何插件处理，也无提示桩响应；菜单文本与指令文档不再列出该指令。

#### Scenario: 群内发送旧指令
- **WHEN** 用户在群聊发送 `/兑换码 TEST-CODE-TEST`
- **THEN** 机器人无任何响应

### Requirement: 兑换码定义维护
兑换码注册表 SHALL 位于 `webapp/profile/redeem_service.py`（代码内定义，条目含描述与回调）；新增或下架兑换码通过修改代码并重启 webapp 完成，不提供网页管理界面。

#### Scenario: 下架
- **WHEN** 注册表移除某码并重启
- **THEN** 该码提交时按未知码拒绝；历史记录仍保留并显示通用占位说明
