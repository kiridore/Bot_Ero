# 生成图水印

## Why

机器人生成的图片会被截图转发，作者身份随之丢失。所有者需求：在机器人生成的图中加入作者（上传者）名称水印——45° 旋转、交错排列、半透明白色字体，默认开启（全员防盗，可自行关闭）；多人卡片（积分排行榜、本周打卡板）不加水印，但受"隐私·昵称与头像公开开关"提案的行级匿名影响（所有者已裁定 Q4:A、Q5:B）。

## What Changes

- 新增个人设置 `watermark.enabled`（布尔，**缺省 True=开启**）。
- **单主体**生成卡（个人档案卡，`/档案` 指令与 `register.completed` 注册图两个入口）在生成末尾叠加主体展示名平铺水印：
  - 样式固定：作者名称文字旋转 45°、相邻行错位半个周期交错平铺、半透明白色；不透明度与平铺间距为固定常量，不新增配置。
  - 水印文字与卡头使用同一主体展示名。图片可传播，**两个入口均无网站本人豁免**：`privacy.identity_public=False` 时卡头与水印都用 `anonymous_name(uid)`（QQ 号 MD5 前 8 位），头像用 `generate_identicon(uid)`，不取真实头像。公开时 `/档案` 保留既有群名片/昵称回退，注册图保留 `str(uid)`，不新增昵称请求。
- **多人卡片**（积分排行榜、本周打卡板）任何情况不加水印——整图平铺水印只能承载一个名字，多人卡无法单一归属。
- 设置页新增"图片水印"分组，开关"在我的个人生成图上加水印"（默认开）。
- 依赖：匿名名函数来自提案 `privacy-identity-display`，先实施该提案。

## Capabilities

### New Capabilities
- `generated-image-watermark`：水印开关与缺省值、单主体卡水印规则、多人卡排除、水印文字与身份隐私联动。

### Modified Capabilities
无。

## 范围与排除

- 不给用户上传的打卡照片/相册图加水印（所有者定义限"机器人生成的图"；原图经 `/media/`、`/thumb/` 直出不变）。
- 不加水印内容/样式/角度/透明度的任何配置（固定常量，遵循"不增加多余配置"惯例）。
- 多人卡片不做按行水印（所有者已裁定排除）。
- 不做水印位置防裁剪等对抗性设计（平铺本身已覆盖全图）。

## 执行 Ruling：1.57.0 同批个人偏好发布与验收边界

- 三个独立提案 `privacy-identity-display`、`timeline-feed-preference`、`generated-image-watermark` 保留各自能力与验收标准，但作为同一批个人偏好变更统一发布 **1.57.0**（基线1.56.0）；原先按实施顺序写出的中间版本安排作废，不代表曾发布或需要分别发布。
- 代码、版本及文档在同批交付中同步；本次仅更新版本与文档、执行验证，不 commit/push/archive。不得因自动测试通过而删除真实客户端验收标准。
- 网站本人豁免与可传播 bot 图片不豁免分别适用；匿名身份只隐藏昵称头像，不隐藏账号关联、不替换用户正文或回写历史数据。两种多人图只逐行匿名、无水印；两个个人档案入口共用展示身份与水印规则，上传原图不变。
- 实际 Chrome + 临时配置/数据库 + 本地 webapp API 的联动与截图检查可以验证网站行为；OneBot身份资料/发送模拟不等于真实QQ客户端。真实QQ群聊、私聊档案及注册图视觉验收仍保留待验收，不归档。逐条证据与剩余事项见 [acceptance.md](acceptance.md)。
