# 实施核查与裁定

## 数据层

- `redeem_code_usage` 表不变，迁移前记录原样可查；`RedeemManager` 收敛为事务内占位＋历史查询，旧 `claim()/release()`（先提交占位、失败再删）随之删除——中途崩溃不再留下"已占位未发奖"的脏行。
- 回调契约从 `callback(db, user_id, api)` 简化为 `callback(db, user_id)`：现有两个回调从未使用 api 参数；网页服务无 QQ 上下文。

## 展示与过滤

- 历史列表的"已下架"码显示通用占位说明，不把注册表旧文案（可能含奖励细节）留在用户可见输出里。
- `plugins/weekly_report/_is_redeem_code` 保留：群里仍可能有人手输旧指令文本，该过滤器继续把这类消息排除出周报精选引用，行为无害。

## 版本与分支

- 基于 master 1.57.0，版本 1.58.0；独立分支，不自动合并/推送。

## dev 同步警示（后续合并 dev 时执行，本轮不做）

dev（社区线 1.51–1.56）上的 redeem_code 与 master 旧版有语义差异，合并时不能直接取一方覆盖：

1. dev 侧插件带 `requires` 依赖检查（称号关闭时整次拒绝、不核销）与黑名单快照拦截（被封账号静默拒绝）。迁移到网页后，同等约束需在 `redeem_service` 接入：被封账号网页兑换也应拒绝；称号类兑换码在称号插件关闭时应拒绝且不核销。
2. dev 的插件发送走统一输出模块；本次删除的是 master 旧版直发实现，无冲突残留。
3. 社区规划文档（docs/community/*.md）中的功能包清单仍列 redeem_code，属 dev 域文档，本轮不动；dev 合并时随其计划文档一并更新。
