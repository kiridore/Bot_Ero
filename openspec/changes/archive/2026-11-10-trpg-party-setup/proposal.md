# 跑团开团前准备与准入校验（指令统一到 `/跑团`）

## Why

所有者指令（2026-11-10）：

> 记录开始之前需要对群里成员标记进行校验，除了标记为 dm 和 ob 的群成员，所有群成员都需要设定自己的当前角色。如果并非所有群成员都有标记或选择了角色卡，将拒绝开始录制。同时需要对开团前的设置功能进行完善，除了观察者以外，其他人都需要使用「/跑团 准备」进行准备，所有参与玩家准备后，会弹出提示，显示 DM 和参与玩家以及对应的角色卡供玩家确认。确认无误后 dm 使用「/跑团 记录 开始」来开始记录。将「/跑团记录」指令改为 /跑团 指令下的子命令。

现状（读源码确认）：

- 任何人发 `/跑团记录 开始` 就能开录，**没有任何准入校验**：没有 DM 也能开、玩家没有角色卡也能开，参与者与角色卡的对应关系全靠人记；
- `.dm` / `.ob` 只存在内存 `core/context.py::group_roles`，重启即丢；
- 指令散落在 `/跑团记录 …` 与 `/角色 …` 两处，开团前设置没有统一入口；
- 机器人无法获得群成员名单（`core/api.py` 只有单人查询），因此"全员校验"目前无法实现。

所有者的运营模型（本次澄清）：**一个群只跑一场团，跑完即解散；群名就是团名，群成员就是 DM + PL + OB + 机器人**。因此"全体群成员都必须是参与者"在本场景成立，可以按字面执行全员校验。

## What Changes

### 1. 指令树统一到 `/跑团`

| 新指令 | 说明 |
|---|---|
| `/跑团` | 无参数：输出准备情况卡片（同 `/跑团 名单`） |
| `/跑团 准备` | 玩家准备：登记账号当前角色卡快照；无角色卡则提示去网页车卡 |
| `/跑团 取消准备` | 撤销自己的准备 |
| `/跑团 名单` | 重新打印准备情况卡片 |
| `/跑团 记录 开始` | **仅 DM**，通过准入校验才创建记录 |
| `/跑团 记录 强制开始` | 跳过校验直接开录（沿用旧语义：丢弃上次未导出记录） |
| `/跑团 记录 结束` / `导出` / `列表` / `#N` | 与旧 `/跑团记录` 同名子命令等价 |
| `/跑团 角色 查看` / `列表` / `切换 <编号>` / `删除 <编号>` | 由 `/角色 …` 迁移而来 |

- 旧 `/跑团记录 …` 与 `/角色 …` **彻底停用**（无任何插件响应，无提示桩）。
- `plugins/menu/bot_menu_text.py` 同步为上述指令，删除旧行。

### 2. 群成员角色标记

- 保留 `.dm` / `.ob` 两条设为自身角色的指令（不改名为子命令）。
- DM **唯一**：设新的 DM 时顶掉旧 DM；同一人设 OB 会清掉其 DM，设 DM 会清掉其 OB。
- 角色标记与准备名单一起落盘（见第 6 节），重启不丢。
- 角色标记只对**当前群成员**生效：已退群的人即使留在文件里也不参与校验。

### 3. 准备流程

- `/跑团 准备` 读取 `core.character_store.get_current(user_id)`；无卡时回复车卡链接并**不标记准备**。
- 准备时把角色卡关键字段快照进名单（角色卡 id、角色名、种族、职业、等级），之后玩家切换角色卡不影响本场记录。
- 每次准备/取消准备/角色标记变化后，刷新准备情况卡片（Q2 选择"实时卡片"，DM 自行决定何时开录）。
- 卡片内容：DM（昵称、是否在群）、已准备玩家（昵称 → 角色名/种族/职业/等级）、未准备成员（@ 提示）、观察者名单。

### 4. 开录准入校验（`/跑团 记录 开始`）

仅 DM 可执行；超级用户可代 DM 执行（视为通过"执行人"检查）。校验顺序：

1. **成员名单可达**：`get_group_member_list` 成功返回（失败 → 拒绝，提示后端未响应；`强制开始` 可绕过）。
2. **DM 存在且是群成员**：`roles` 中恰好一人为 DM，且该人在成员名单内。
3. **无角色卡者**：除机器人、DM、观察者外的所有群成员，`character_store.get_current` 必须非空。
4. **未准备者**：同上集合的每个人必须在准备名单内。

失败时**一条消息列出全部缺失项**（不是只报第一个）：缺 DM / DM 不在群 / 缺角色卡的成员 @ 出来并附车卡链接 / 未准备的成员 @ 出来。

### 5. 开录时写入记录（与既有录制流程衔接）

- 记录 `meta.json` 的 `participants` 由准备名单预置（含 `user_id`、`nickname`、`char_name`、`role`），`roles` 取当时的 DM/OB 标记；此后发言只补充未在名单内的人。
- 开录成功后清空该群 `pending.json`（准备名单与角色标记一并清掉——本场团已开始，群的使命接近结束）。
- 录制期间 `/跑团 准备`、`/跑团 取消准备`、`/跑团 名单` 回「录制中无法准备」；`/跑团 记录 开始` 回「当前已在录制中」。

### 6. 准备状态持久化

- 新文件 `server_data/trpg_records/<群号>/pending.json`（与记录目录同根，写用 tmp + `os.replace`，读失败按空处理并记 warning）。
- 结构：`{version: 1, group_id, roles: {user_id: "dm"|"ob"}, prepared: {user_id: {user_id, nickname, char_id, char_name, race, class_name, level, prepared_at}}}`。
- 群成员退出后，其准备记录保留到下次校验时被忽略，不做主动清理。

### 7. 群成员列表接口

- `core/onebot_client.fetch_group_members(group_id)`：HTTP `get_group_member_list`（`no_cache: false`，超时 5 秒），返回成员数组；失败返回 `None` 以便与"群里没有成员"区分。
- 需要让 `_call_onebot` 支持数组型 `data`（当前只接受 dict，会吞掉列表返回）。
- 不使用 WS `call_api`（30 秒阻塞，会把开录拖死）。

### 8. 网页侧与文档

- 网页记录列表/详情文案把「群名」统一为「团名」（数据字段仍是 `group_name`，不迁移旧数据）。
- 网页无需新接口：`meta.participants` 预置后列表自动显示完整参与者。
- `CHANGELOG.md` 新增 `[1.63.0]`，`BOTERO_VERSION` bump 至 1.63.0；`plugins/menu/bot_menu_text.py`、`kb/PLUGIN_CATALOG.md`、`specs/plugin-catalog.md`、`kb/QUICK_REFERENCE.md` 同步指令表。

## Capabilities

### New Capabilities

- `trpg-party-setup`：群成员角色标记（DM/OB）与唯一性、准备名单与卡片、开录准入校验的判定规则与失败提示、`pending.json` 持久化、`/跑团` 指令树。

### Modified Capabilities

- `trpg-session-recording`：`录制即落盘` 要求改为「参与者与角色从准备名单预置，录音期间只补充名单外的人」；同时明确开始录制只由 DM 经准入校验触发（校验细则见 `trpg-party-setup`）。

## Scope and Compatibility

- **一个群只跑一场团**是本次校验成立的前提（所有者明确）：群名即团名，群成员即 DM + PL + OB + 机器人。若将来出现"一个群长期复用、成员流动"的场景，本校验会把潜水成员算成缺卡者，需要重新设计（届时改为显式报名名单）。
- **豁免**：机器人（`BOT_QQ` 与 `is_robot` 成员）不参与校验；DM 与观察者不需要角色卡、也不需要准备。
- **不做**：多团并存、请假/缺席登记、临时角色、网页端准备、按群配置开关。
- **兼容性**：旧 `/跑团记录 …` 与 `/角色 …` 不再响应；升级前若存在"已结束未导出"的记录（只存内存），重启后无法再导出——部署升级前应先导出。
- **新依赖外部能力**：`get_group_member_list` 需 OneBot 后端支持（LLOneBot 已确认有该接口，见 `specs/llms.txt` 第 34 条）；不可达时拒绝开录并给出原因，`强制开始` 可绕过。
- **社区版与私有版一致**：无版本差异，无 edition 分支。
- **无数据库变更**，无新增第三方依赖。
