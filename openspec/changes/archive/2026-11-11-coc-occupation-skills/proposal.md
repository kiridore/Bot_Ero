# COC 职业本职技能结构化与校验

## Why

人物卡 xlsx 的「本职技能」是散文（`会计，法律，图书馆，聆听，说服，侦查，任意其他两项个人或时代特长。`），1036 个片段里 311 个对不上技能表——含可选池描述、句末标点、别名不一致。结果是**职业点可以加到任何技能上**：`validate()` 只校验总点数不超预算，从不校验加在了哪些技能上，与 7 版规则不符。

## What Changes

- 新增数据文件 `core/trpg/occupation_skills.json`：113 个职业各一条结构化本职技能定义
  ```json
  "90": {"required": ["会计", "法律", "图书馆使用", "聆听", "说服", "侦察"],
         "choices": [{"count": 2, "from": "*"}]}
  ```
  - `required`：固定本职技能（全部使用 `SKILL_BASE` 规范名）
  - `choices`：可选池，`{"count": n, "from": [技能…]}` 表示从池中选 n 项；`"from": "*"` 表示任意技能
- `core/trpg/coc_data.py` 载入该文件，保留原散文 `own_skills` 仅用于展示
- `coc.validate()` 新增职业点归属校验：职业点只能加在 `required` 或各 `choices` 配额内，越界返回 400 并指出具体技能
- 建卡页在本职技能提示后标注哪些项属于可选池
- 下拉过滤掉 xlsx 里两条工具残留（seq 0 说明长句、seq 1「自定义职业」按自定义处理）

## Capabilities

### Modified Capabilities

- `coc-character-sheet`：本职技能结构化、职业点归属校验。

## Scope and Compatibility

- 职业点**总额**校验不变（仍按公式算预算），本次只多一层「加在哪」的校验。
- 已验证的卡若曾把职业点加在非本职技能上，保存会被拒并在消息里指出是哪项。
- 自定义职业（seq 1）按「任意 8 项」处理。
- 数据以 JSON 落在 `core/trpg/`，与 `coc_data.py` 同目录，便于人工审阅与后续修正。
- 无数据库变更、无新增依赖。

## 数据裁定（执行期 Ruling）

并行整理时出现的三类歧义，按下列口径统一，写入数据前先规范化：

1. **「任一专攻」写法**：一律 `类别:*`（半角冒号 + 星号），类别限于 技艺 / 格斗 / 射击 / 语言 / 母语 / 生存 / 科学 / 驾驶 / 罕见；计数按 1 项。合并时把 `类别:任一`、`类别:任意`、裸类别名统一改写为 `类别:*`。
2. **表外技能名**：`驯兽`（饲养员）记为 `技艺:驯兽`；`潜水`（替身演员）优先 `游泳`，若该职业已有游泳则记 `技艺:潜水`。除此之外不得自造基础技能名。
3. **校验语义**：`occupational_point_problems()` 对 `类别:*` 按类别前缀匹配（`语言:英语`、`技艺:烹饪` 均通过），普通固定项仍精确匹配；`类别:*` 不跨类别放行。
