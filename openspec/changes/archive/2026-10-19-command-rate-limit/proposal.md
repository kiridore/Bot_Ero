# 每账号指令频率限制

## Why

公开机器人服务多个群和私聊账号，需要防止同一用户无限调用指令。已有community.cmd_cooldown_seconds只是同指令冷却配置，不能代替本次已确认的跨指令总次数限制。

## What Changes

- 同一机器人实例内按QQ账号合并群聊与私聊的指令次数，滚动60秒最多20次。
- 只计算匹配到当前允许执行的指令的消息；一条消息只占一次，多插件匹配或一键批量业务不额外计数。业务执行后报错也不退次数。
- 超限整条指令不执行业务，不新增计数、不延长等待。普通聊天、未匹配指令、后台事件不计数。
- 群聊在原群提及用户提示，私聊在原私聊提示；显示剩余等待秒数，同账号跨位置每10秒最多提示一次。
- 超级用户与普通用户同规则；内存保存，重启清空，检查与计数原子完成。
- 新增community.command_limit_per_minute：缺省0表示关闭，公开模板填20。窗口60秒及提示间隔10秒为本功能固定规则，不增加多余配置。
- 不新增edition分支，不写数据库，不改变已确认的权限、注册、群审核及部署边界。

## Capabilities

### New Capabilities
- `command-rate-limiting`：账号滚动窗口、计数边界、超限提示和配置兼容。

### Modified Capabilities
无。现有通知/开关/输出规范继续适用；此提案新增执行前约束，不替换既有业务规则。

## 范围与排除

不实现黑名单，不实施同指令冷却，不新增整体资源配额、后台限速或全部文案外置；不把一次一键抽奖拆成多次计数。该限制衡量指令消息数，不能保证不同指令的资源成本相同。

不按消息以/开头简单计数：无效指令不计，合法非斜杠指令也必须覆盖。未开放插件不参与本次计数；“获准执行”指通过既有部署、注册、群审核、插件开关和匹配条件，不增加对所有插件业务内部校验的提前探测。

## 验收标准

以下测试文件在实现时新增，当前提案阶段不声称已经通过。

| 标准 | 独立执行 | 通过条件 |
|---|---|---|
| AC01 | `python -m pytest test/test_command_rate_limit.py -k window` | 60秒内前20条获准、第21条拒绝；恰好满60秒的记录失效；仅过期记录释放额度，非自然分钟清零；拒绝不延长等待 |
| AC02 | `python -m pytest test/test_command_rate_limit.py -k concurrency` | 并发超过20次时恰好20次获准，无超额；不同账号互不占额度；重启/新实例无计数，过期数据可清理 |
| AC03 | `python -m pytest test/test_command_rate_limit_entry.py -k counting` | 群A/群B/私聊同账号共享额度；普通聊天、未匹配、未开放及后台事件不计；非斜杠和自定义指令覆盖；多插件/批量一次，执行失败仍占一次 |
| AC04 | `python -m pytest test/test_command_rate_limit_entry.py -k rejection` | 超限时所有匹配指令业务均不执行，无扣费、写库、内部奖励通知；正常时原处理次序保持；match不写限流状态；超级用户也受限 |
| AC05 | `python -m pytest test/test_command_rate_limit_entry.py -k reminder` | 原位置提示、群聊提及用户、剩余秒数向上取整；同账号跨位置10秒至多一次；提示失败不重新执行业务、不自动重发 |
| AC06 | `python -m pytest test/test_command_rate_limit_config.py` | 缺键/0关闭，公开模板20；负数/布尔/非整数拒绝；启动与面板共用校验；旧配置兼容、仅改edition不影响行为，旧冷却配置不被重新解释 |
| AC07 | `python -m pytest`及`openspec validate command-rate-limit --strict` | 全量绿，入口分类清单无遗漏；文档/帮助/配置/版本/CHANGELOG同步；临时副本验证归档后，正式归档与实现同commit |

## 维护者可持续性影响

减少刷指令引起的人工处置；无需新服务或数据库表。超限提示本身限频，过期账号内存须能回收。不替代黑名单与真实服务监控，不承诺防住多账号协同滥用或单次高成本指令。
