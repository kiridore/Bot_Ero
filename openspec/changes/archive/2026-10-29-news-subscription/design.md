# 设计 — 新闻订阅插件

## 已确认范围

本次由所有者明确指定在 master 实施。插件 ff_news 更名 news，消息源只含 FF14 国服官网；订阅绑定账号，群聊管理，推送仅默认群。沿用 master 心跳路径，不新增默认群插件开关检查，不引入 dev 的黑名单或输出模块。

## 数据与代码结构

- `core/db/_base.py::init_schema` 幂等创建 `news_subscriptions(user_id INTEGER, source_id TEXT, subscribed_at TEXT)`，用户与源联合主键；以及 `news_push_state(source_id TEXT PRIMARY KEY, cursor TEXT, updated_at TEXT)`。
- `core/db/news.py::NewsManager` 提供幂等订阅、退订、查状态、取订阅者、读写游标；通过 `DbManager.news` 装配。查询使用参数占位符。
- `plugins/news/__init__.py` 的 NewsSource/NewsItem 与 `_SOURCES` 是唯一消息源定义；稳定 key 入库，列表序号从 1 起展示。现有编号不得通过重排改变；新增源追加。
- 指令复用 `on_command_any`，仅 message 事件匹配；私聊进入 handle 后拒绝，不写订阅。列表显示已订阅或未订阅；无效编号、多余参数不写库。

## 抓取与推送

1. 每整点、半点检查。match 不更新调度状态；handle 用进程内锁与分钟键去重，避免并发心跳重复执行。
2. FF14 官网列表存在置顶排序。实测小写 pageIndex 生效，服务端 pageSize 上限 50。读取 PageCount 对应全部页面（上限 200 页，异常时整源失败），按数字 Id 去重排序，不能以第一页等于最新新闻为前提。任何页失败不提交部分结果。
3. 首次没有游标时，只记录当前最大编号，不补历史。后续只处理编号大于游标的条目，按编号从小到大处理。
4. 无人订阅或发布已超过 48 小时：不发送，推进该条游标。未来条目不发、不越过它推进游标。
5. 有订阅者时，逐条调用现有 send_msg：AT 全部订阅者（数字字符串 QQ）、标题/摘要/链接、可选图片；称号由框架注入。心跳无用户/群上下文，框架路由默认群。
6. 发送确认成功后逐条推进；返回 0 或抛异常则停止该源本轮发送，已成功的条目不重发，下轮重试失败条目。没有默认群时发送返回 0，不推进失败条目。抓取失败只影响本源。
7. 官网旧列表不会倒退游标；订阅者采用本轮查询快照。订阅后可能收到上次轮询之后、订阅之前发布的条目，不承诺精确以订阅秒数截断。

## 可靠性边界

- 按数字编号判定新条目，修改已有公告或旧编号重新发布不视为新消息；当前仅支持这一类源。
- QQ 发送与 SQLite 无分布式事务：发送已到达但确认丢失、或发送后进程在保存游标前退出，下轮可能重发。不能声称严格恰好一次。
- 单源全部分页请求同步执行，每页超时 25 秒；不新建线程或后台队列。超过 200 页失败并记日志，届时需调整抓取策略。
- 不改用户部署配置；若部署自行配置了 ff_news，需改名 news。不能从代码仓库推断所有实际部署均没有旧配置。

## 验证

`test/test_news_subscribe.py` 使用 pytest 会话临时配置/数据库、test.helper 消息夹具、假 fetch 和模拟 API；验证订阅、退订、跨群全局共享、私聊拒绝、非法参数、半小时调度、游标、失败重试、分页、默认群路由、称号与图片。真实官网只做只读接口验证；不连接 QQ、不触碰真实数据库。

## 执行裁定

- 原脚本测试改成进程内 pytest，符合现有 bot 插件测试布局。
- 原取前 10 条改为完整分页，依据真实官网存在置顶与页大小限制，防漏抓。
- 保留已确认的数字编号游标，不增已推送记录集合或多群订阅。
- master 的原菜单文件仍是唯一文案来源；不采用 dev 的结构化菜单。
