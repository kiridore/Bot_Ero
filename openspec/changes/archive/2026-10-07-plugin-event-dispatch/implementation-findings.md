# 实施前核查发现

## 已裁定：称号关闭时暂时禁止抽奖

核查 plugins/lottery/rewards.py 后发现，称号并不只是抽奖后的附加解锁提示：

- REWARD_TABLE 里普通/稀有/传奇称号分别占 12%/5%/4%，合计 21%。
- draw_reward 会直接调用 draw_title_by_rarity；后者写入 dbmanager.titles.unlock。
- 已拥有称号会按稀有度返还 1/2/3 积分。
- plugins/lottery/__init__.py 中 evaluate_and_unlock_titles 是另一条称号发放路径，只移除这四次评估调用不能达成关闭称号后停止新奖励。

提案同时要求「关闭称号停止新称号奖励」和「保留抽奖概率、扣费、奖品规则」。在抽奖开启、称号关闭的组合下，无法同时原样保持两者。必须先由所有者确定处理方式，不能擅自重新分配概率、丢弃付费结果或改变退款金额。

可选：禁止该组合下抽奖并在任何扣费/次数消耗前说明依赖；或者规定关闭称号时称号奖项的替代处理。前者不改奖表，但暂不支持抽奖与称号完全独立。

所有者确认：暂时禁止抽奖。对单抽和一键抽奖，在任何扣费、次数消耗、道具消耗、随机抽取之前检查本次操作的称号开关；关闭时提示原因并返回。抽卡消费查询保持可用。本项作为独立开关的明确依赖例外，不调整奖品概率或退款金额。

验收：账号与群两种关闭场景下，单抽/一键抽奖均不写积分、抽奖次数、道具或奖品记录；开启时保持原奖表；消费查询不受限制。纳入 AC03/AC08 的集成测试。
