# Design

## 1. 查询和修改分别解析

现状：group_manager._parse通过_resolve_target_gid将无目标私聊解释为0；_list_plugins_text读取group_plugin_config，账号查询分支才读取enabled_plugins(user_id)。注册_seed_default_pack写user_plugin_config；菜单使用Operation.enabled。

先识别只读列表，再解析查询目标：

| 列表后参数 | 查询目标 |
|---|---|
| 无参数，私聊 | 发送者账号 |
| 无参数，群聊 | 当前群 |
| 用户 <正整数> | 指定账号私聊 |
| 群 <正整数> | 指定群 |
| 公共默认 / 0 | 私聊公共默认 |
| 旧单个正整数 | 指定群（兼容） |

旧列表中可解析的动作标记不得变成写入。非法/混合目标回用法，不猜测，缺少发送者账号时不得回落到公共默认。保留现有账号/群号整数边界校验。

写操作继续走现有路径。新“公共默认”仅作为查询语法，不暗中扩展写语法。所有入口先检查超管身份。

## 2. 一份只读结果供两类列表使用

优先复用core.db.plugin_settings.enabled_plugins、部署许可、注册和群审核规则；需要原因时提供最小只读辅助结果，不把业务执行或消息提醒函数当作查询调用。不得触发提醒限频写入、自动注册、审批、奖励或开关修复。

每次查询先确定目标并读取状态，再同时用于逐项展示与包汇总；不在包循环中反复查询不同时间的状态。账号目标的注册及超管豁免都依据目标账号，而非执行查询的管理员。群目标不额外套用发送者私聊设置。

原因顺序：部署未开放 → 目标未获准使用（未注册/群未批准）→ 插件关闭 → 开启。多个限制并存至少显示最高优先级原因，必要时附保存的开启设置；读取状态失败显示“无法确认”，不伪装关闭或可用。数据库故障保留日志，不回显内部错误。

系统插件受部署和准入限制，但不按普通账号/群开关关闭。注册中的允许入口和超级用户豁免与实际运行逻辑一致；不得为了让菜单看起来正常另造放行规则。群审核关闭时不因登记缺失限制；注册require关闭时不因账号未登记限制。

公共默认没有具体注册身份或群审核状态，只显示部署约束下的默认开关和系统属性，标题明确“继承规则，不代表某账号实际可用”。

## 3. 展示与统计

- 标题必须包含范围及目标编号；公共默认注明没有该插件单独设置的账号继承此值。
- 账号行注明单独设置/沿用公共默认；单独关闭仍属单独设置。
- 部署禁止或准入阻止时，可补“已保存开启设置”，但不能同时用开启图标宣称实际可用。
- 插件注册表按plugin_key去重，同模块多个插件类不重复展示。
- 包成员先去重。分母为部署允许的非系统成员，分子为这些成员中当前目标实际可用数；额外说明被部署排除成员数。无可计数成员时区分仅含系统项与部署全部未开放，不能用0/0暗示全部可用。
- 未批准群/未注册普通账号的业务包分子为0；系统例外不混入包统计。
- 公共默认显示“默认开启 x/y”，不使用具体账号“可用 x/y”的表述。

## 4. 兼容提醒

无目标私聊列表追加提示：本列表是当前账号；无目标开启/关闭仍修改私聊公共默认，修改此账号请显式写“用户 <账号>”。公共默认标题说明影响继承账号。

无目标私聊修改回执将“全局”换为明确“私聊公共默认”，说明未单独设置的账号受影响；群回执仍明确群号。同步插件与功能包两种指令、菜单条目和community文案包，不改变写入目标。

## 5. 实施与验证边界

在隔离配置及临时DB下，运行注册发包真实路径，再执行真实group_manager列表，并与账号有效设置和菜单对照；不能只测渲染字符串。群/账号/公共默认构造不同设置，验证不会互相混入。

增加部署禁止、账号显式关闭、超管目标、未注册非超管目标、未批准群、读取失败、多类同模块、部分/全部禁止包场景。原管理测试保持写入对象断言；查询前后比对业务表，不能让查询改变设置。

不改OneBot协议和旧发送机制，不新增依赖。只要发现要修改运行期放行规则才能对齐，应先记录为独立问题，不借显示修复改变业务授权。

完成后patch版本、CHANGELOG、specs/plugin-catalog、kb/PLUGIN_CATALOG与QUICK_REFERENCE、操作手册同批同步，完整验收后归档。当前只生成提案，不实现、不归档。
