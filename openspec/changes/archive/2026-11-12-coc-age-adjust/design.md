# 设计：COC 建卡年龄调整

## 规则表（来源：守密人核心规则书 创建调查员流程）

| 年龄 | 体能（合计） | 体能项 | APP | EDU | 幸运 | MOV |
|---|---|---|---|---|---|---|
| 15–19 | −5 | STR + SIZ | 0 | −5（定值） | 掷两次取高 | 0 |
| 20–39 | 0 | — | 0 | 成长检定 ×1 | — | 0 |
| 40–49 | −5 | STR / CON / DEX | −5 | 成长检定 ×2 | — | −1 |
| 50–59 | −10 | STR / CON / DEX | −10 | 成长检定 ×3 | — | −2 |
| 60–69 | −20 | STR / CON / DEX | −15 | 成长检定 ×4 | — | −3 |
| 70–79 | −40 | STR / CON / DEX | −20 | 成长检定 ×4 | — | −4 |
| 80–89 | −80 | STR / CON / DEX | −25 | 成长检定 ×4 | — | −5 |
| 90+ | 同 80 | STR / CON / DEX | −25 | 成长检定 ×4 | — | 每十年 −1 |

EDU 成长检定：掷 1D100，结果 > 当前 EDU 则 EDU += 1D10（上限 99）。

## 数据结构

```json
"age": 45,
"age_adjust": {
  "kind": "applied",
  "age": 45,
  "band": "40-49",
  "phy": {"str": -3, "con": -2, "dex": 0},
  "app": -5,
  "edu": {"before": 60, "after": 68, "checks": 2,
          "rolls": [{"roll": 71, "gain": 8}, {"roll": 40, "gain": 0}]},
  "before": {"str": 63, "con": 57, "dex": 55, "app": 55, "edu": 60, "siz": 45},
  "applied_at": 1794489600
}
```

- `kind: "applied"`：已应用，参与全部校验。
- `kind: "skipped"`：玩家选择「不再提示」，只记 `age` 与 `band`，不参与数值校验；年龄改变后重新提示。
- 字段缺失：未处理（既有卡），不拦保存。

撤销 = 按 `before` 还原属性与 EDU，删除 `age_adjust`。

## 校验（`validate`）

1. `age` 为 0（未填）→ 跳过年龄相关校验；非 0 必须是 15–99 的整数。
2. `kind == "applied"`：
   - `age_adjust.age == data["age"]`，否则「年龄已从 45 改为 50，请重新应用或撤销年龄调整」
   - `phy` 的键集合等于该年龄段的体能项，每项 ≤ 0，合计等于额度，否则「体能合计应扣 5 点，当前为 3 点」
   - `app == 该段 APP 额度`
   - `before[键] + delta == 当前属性`（对应项），否则「年龄调整后请勿手工修改力量/体质/敏捷/外貌/教育，如需修改请先撤销」
   - 调整后属性落在 1–99
3. `kind == "skipped"`：只校验 `age` 与记录年龄一致，不一致时忽略（不拦保存）。

## 接口

- `POST /api/me/characters/{id}/age-adjust`
  - `{"action": "apply", "phy": {"str": -3, "con": -2, "dex": 0}}`
  - `{"action": "skip"}`
  - 服务端按年龄重算 APP 与 EDU（15–19 的 EDU −5 是定值，其他段掷成长检定），写 `age_adjust`，返回 `CharOut`
  - 校验失败 400 + 中文原因
- `DELETE /api/me/characters/{id}/age-adjust`：撤销
- 现有 `PUT` 忽略请求里的 `age_adjust`（一律保留卡上原值），避免建卡页整卡回写时覆盖

## 页面

年龄输入框下方「年龄调整」区块：

- 未处理/已跳过：按年龄段显示应做的调整 + 体能分配输入（3 个或 2 个数字框）+「应用年龄调整」+「不再提示」
- 已应用：显示明细（含 EDU 掷骰结果）+「撤销」；被调整的属性输入框加 `readonly`
- 15–19：幸运行多一个「掷两次取高」按钮
- 体能输入框限制为 ≤0，三项之和 ≠ 额度时「应用」按钮禁用并显示差额

## 取舍

- **服务器掷 EDU**：与升级向导的 HP 掷骰同一思路，避免刷新页面重掷。
- **撤销后重应用会重掷 EDU**：不做防重掷（`shortcut: 允许反复应用重掷 EDU 成长检定，若需要防重掷再复用已存 rolls`）。
- **不做逐十年老化指令**：玩家改年龄后重新应用即可。
- **不迁移旧卡**：自动扣属性会破坏玩家已录入的最终值。
