# 周更日志（QQ 群公告）

把一段时间的仓库提交转成一篇发到 QQ 群的更新公告。读者是群友（板油），不是开发者。

## 步骤

1. **圈定窗口**

   - 默认本周一 00:00 至今；用户给了范围（"上周"、"八月的"、某 tag/commit 起）则用用户的。
   - `git log --since="<起点>" --pretty=format:"%h|%ad|%s" --date=format:"%Y-%m-%d %H:%M"` 拿全量提交。
   - 完成判据：拿到提交清单，并说出窗口对应的 CHANGELOG 版本区间（`chore(版本)` 提交是版本界桩）。窗口内零提交 → 直接告知用户本周无更新，不编造。

2. **交叉核对内容**

   - 提交 subject 只用来分组计数；用户可见内容的权威描述是 `CHANGELOG.md` 对应版本节。提交日期 ≠ CHANGELOG 日期，窗口按提交日期算。
   - `[未发布]` 节里的纯测试/文档/内部重构条目默认不进公告。

3. **事实核验**

   - 公告里每条会被群友当真的表述（默认开还是关、数值、比例、触发条件、入口在哪）都要落到 CHANGELOG 原文或源码；提交信息没写的默认值必须查源码确认（例：开关默认值查 `core/user_settings.py`）。
   - 完成判据：公告中不存在仅凭提交 subject 推断出的行为描述。

4. **过滤**

   - 只保留用户可见变更，test/chore/内部重构剔除；但在给用户的回复末尾附两三行"说明"，交代窗口口径、剔除项与已核验的事实，供其取舍。

5. **成文**（格式与语气见下），直接输出在对话里，除非用户要求落盘。

## 格式与语气

骨架：

```
【小埃同学·本周更新日志】（M.D - M.D）

各位板油好，……

一、<大功能标题>（本周重点！）
二、<次级功能/玩法>
三、……

以上就是本周全部更新。……感谢……

小埃同学 运营组
2026 年 M 月 D 日
```

语气规则：

- QQ 群口语，短句。称呼群友为「板油」，落款固定「小埃同学 运营组」+ 当天日期。
- 板块顺序：大功能在前（可标"本周重点！"），小功能次之，修复类收尾；同主题多条提交合并成一个板块。
- 玩家视角：写"设置页多了个开关"，不写"core/user_settings.py 新增键"；指令名用「/仙人彩」格式原样保留。
- 术语翻译成人话："原子化"→"一分都不会丢"、"存储型 XSS"→"能塞恶意代码的漏洞"。
- 幽默克制：每个板块至多一处括号吐槽；不用 emoji、不用颜文字。
- 漏洞/安全类只说"已修复"+影响面（如"能白嫖积分"），绝不写可复现细节。
- 数字、概率、日期写具体值（如 40% / 15% / 5%），不写"若干""部分"。
- 版本跨度可作收尾彩蛋（"版本号从 1.21 爬到了 1.25.0"）。
