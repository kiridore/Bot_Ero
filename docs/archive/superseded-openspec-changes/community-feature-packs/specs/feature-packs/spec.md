# feature-packs · Spec Delta

## ADDED Requirements

### Requirement: 功能包表按部署形态选择

功能包表 SHALL 由部署形态（bot.edition）决定：私有形态为既有全量包表；社区形态批次 1 仅含"打卡基础"包（打卡、撤回打卡、回滚、周/全量打卡图、本周成员、个人档案；不含补卡与积分排行）。功能包管理指令展示的包列表随所在形态的表。

#### Scenario: 私有形态包表不变

- **WHEN** bot.edition = private
- **THEN** 功能包表与引入双表前逐项一致，含全部既有包与成员

#### Scenario: 社区形态批次 1 仅打卡基础

- **WHEN** bot.edition = community
- **THEN** 功能包表仅含"打卡基础"包，不含补卡、积分排行及任何经济类插件；/功能包 列表相应只显示该包

### Requirement: 打卡与经济解耦

部署形态未提供经济能力时，打卡域（打卡/撤回/回滚）SHALL 不触达经济引擎：不发放/扣减积分、不评估称号解锁、不触发或回滚周常任务进度；打卡记录、回执消息与时间线事件行为保持。经济能力存在时行为与解耦前一致。

#### Scenario: 社区形态打卡纯记录

- **WHEN** 经济能力未提供，用户完成一次带图打卡
- **THEN** 打卡落库成功、回执正常发送，积分余额不变、无称号解锁评估、无周常进度写入

#### Scenario: 私有形态行为等价

- **WHEN** 经济能力存在（私有形态），用户完成一次带图打卡
- **THEN** 积分奖励、称号解锁、周常进度及其消息展示与解耦改造前一致
