# 社区时间线实施计划（2026-08-10）

> 权威设计：`docs/archive/superpowers/specs/2026-08-10-timeline-design.md`（本计划与之一致，冲突以 design/spec 为准）
> 协议：`specs/timeline-protocol.md`；数据库表：`specs/database.md` §社区时间线

**Goal:** 建设社区主页时间线：各系统按统一协议向 Event Server 发送事件，`/` 根路径渲染 Twitter 式时间线（侧边栏功能导航 + 登录态 + 中间无限滚动 feed），登录可见。v1 发送方 = 打卡 + 周常任务；撤回打卡/消息撤回/任务回退联动删除事件。

**Architecture:** Event Server 为 webapp 第 8 个模块 `webapp/timeline/`（非独立进程），HTTP POST 收事件（`BOTERO_EVENT_TOKEN` 系统间令牌），SQLite `timeline_events` 表（`(source,id)` / `(source,dedup_key)` 唯一约束 + INSERT OR IGNORE 幂等），服务器打 `received_at`，keyset 游标分页。bot 侧 `core/timeline_client.py` best-effort 发送/撤回；`{id:<qq>}` 占位符渲染时解析为头像+昵称，未绑定降级「未绑定玩家」。旧导航主页 `webapp/homepage/` 废弃删除，`entries.json` 迁入 timeline 模块作侧边栏数据源。

**Tech Stack:** FastAPI + SQLite（WAL）+ requests + 原生 vanilla JS（无框架），沿用现有报纸风 token（`core/web/static/gallery.css`）。

## Global Constraints

- 发送方统一走 HTTP POST（含 bot 插件），不走共享 SQLite 直写；发送 best-effort，失败仅记日志，不阻塞主流程
- 无 `timestamp`（服务器打 `received_at`）、无 icon、`data` 不解析
- 撤回 = 硬删除；业务回滚必须联动删除对应事件（checkin 按 `checkin:<user>:<date>`，quest 按 `quest:<user>:<week_key>:<quest_id>`）
- 占位符 `{id:<user_id>}` 只接受 QQ 号，渲染时解析
- 提交消息：中文 Conventional Commits（`.githooks` 校验）；文档与代码同 commit
