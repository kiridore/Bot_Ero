# 黑名单管理（1.56.0）

## 启用与升级

所有部署共用一套实现。旧配置缺省关闭，公开模板开启；更新代码不会自动修改已有config.yaml。

```yaml
blacklist:
  enabled: true
```

开启时必须将 `blacklist` 加入 `bot.allowed_plugins`（若已显式限定）及 `bot.system_plugins`。系统插件非空配置是整体替换，须保留本实例原来需要的系统插件，不能只写blacklist。修改后重启。关闭新开关不撤掉已有群审核的黑名单检查。

升级前停止服务并备份数据库（含WAL的一致性备份）；新增operator_id列，旧记录保留原因及时间、操作者显示未知。不靠复制新模板覆盖部署凭证和数据路径。

## 指令（仅超级用户）

```text
/黑名单 添加 用户 123456 原因可省略
/黑名单 添加 群 654321 原因可省略
/黑名单 查询 用户 123456
/黑名单 解除 用户 123456
/黑名单 解除 群 654321
/黑名单 列表 1
```

列表每页10条；重复添加保留首次记录，重复解除报告未在名单中。机器人及当前超管不能被添加，旧记录中的当前超管豁免但记录保留。用户和群同号互不影响。被封群不接受超管指令，须在私聊管理。

## 生效与恢复

- 账号封禁作用于当前机器人实例的全部群和私聊；封群只影响该群，不连带成员在其他地方的使用。
- 新请求静默停止、不占指令额度；已获准整条指令/单条后台任务按原快照完成，含内部通知。封禁不是中断执行中的事务。
- 闹钟、活动、开奖等被拒记录保留；共享图片维护、货架刷新、过期投票清理继续，群公告另外检查。
- 正常群的共同流程继续，但不给被封参与者新免费奖励或主动私聊；既有付费结算权益不没收。批量正负积分都跳过本操作开始时被封的账号。
- 管理员代补卡也不能操作被封账号；私聊不能操作被封群的活动或卧底房间。
- 拉黑本身不扣历史积分、不删除称号；真实撤回旧打卡保留历史清理例外，静默且防重复。部署禁止仍是上限。
- 解除仅移除名单限制，不注册账号、不激活群、不改插件设置。积压沿原规则处理；错过仙人彩开奖窗口的付费注单须人工核查，不自动补开奖、作废或退款。

## 故障处理

读取名单失败拒绝新业务，查看错误日志和数据库可用性；不通过删除名单或直接修改数据库绕过。已获准操作不重读名单。机器人进退群仍只尝试维护事实记录，若数据库也无法写入则记录日志，恢复后核对QQ群实际状态。

群邀请拒绝使用已有申请表保存结果。成功、失败、未知不得混为一谈，重复事件不自动重发；先通过 `/待审` 和QQ实际情况核实，再由原群审核恢复流程处理。好友拒绝每次事件尝试一次，不自动重试，无新增持久去重队列。

管理指令失败不能视为成功，修复后先查询记录。不要在运行中直接SQL编辑黑名单：应用内写入和准入由同一进程锁协调，外部改库不参与此保证。

## 上线前检查

自动测试不替代真实QQ联调。用测试账号和测试群验证添加/解除、无回复且无业务变化、好友及群邀请拒绝、进退群登记、定时任务恢复；确认超管仍能私聊管理，已有付费记录未丢失。记录维护者可持续性影响：无需新服务或定时补偿队列，但异常拒绝及错过开奖窗口仍需人工核查。

范围是QQ机器人及其任务处理；本次没有改造独立网页服务认证，不据此宣称网站登录也已封禁。
