# 逐步开放操作手册（超级用户）

> 适用：config-unification 之后的任意部署（公开/私有用同一套规则）。
> 前置：使用 `config.public.example.yaml` 作为配置起点（`allowed_plugins` 已限定公开首版集合）。

## 原则

- **部署名单**（`bot.allowed_plugins`）决定"本实例最多能提供什么"——名单外插件任何入口都开不了。后续批次开放新功能 = 改配置加名单 + 重启。
- **群/账号开关**决定"具体给谁开放"。新群、新私聊默认全部关闭（系统插件除外）。
- 菜单自动跟随当前位置的开放集合，无需手工同步。
- 关闭只停止后续执行，不删除历史记录与已发奖励。

## 常用操作

| 目的 | 指令 |
|---|---|
| 给某群开放打卡基础 | `/功能包 打卡基础 开启 群 <群号>` |
| 给某群加开单个插件（已在名单内） | `/插件 title 开启 群 <群号>` |
| 给某私聊账号开放 | `/功能包 打卡基础 开启 用户 <账号>` |
| 收回某账号的单独设置（恢复继承公共默认） | `/插件 title 默认 用户 <账号>` |
| 查看某群开关 | `/插件 列表 群 <群号>`；包维度 `/功能包 列表 群 <群号>` |
| 查看某账号私聊设置 | `/插件 列表 用户 <账号>` |
| 设置私聊公共默认（影响所有未单独设置的账号） | 私聊机器人发送 `/功能包 打卡基础 开启`（不带目标=公共默认） |
| 查看部署边界 | `/插件 列表` 中 🚫 = 本部署未开放（需改配置），🔒 = 系统插件 |

## 注意事项

- **公共默认影响面**：不带目标的开启/关闭改的是"私聊公共默认"，所有未单独设置的账号随之变化；管理回执会注明。建议公共默认保持最小集合，按账号单独加开。
- **重新允许旧插件**：把插件加回 `allowed_plugins` 并重启后，该插件**旧的群/账号开启记录继续生效**（记录从未删除）。上线前用 `/插件 列表 群 <群号>` 核对。
- **关闭期间的定时任务**：闹钟不发送不推进、活动不结算、仙人彩不开奖（已付注单保留并在日志中提示）；重新开启后按原到期规则处理，错过窗口的已付费注单由超管人工处置。
- **新装插件**：更新代码引入的新插件不在名单内即不运行；加入名单后还需要给群/账号开启才会对用户可见。
- 修改 `bot.feature_packs_file` 只改批量操作的分组，不会自动开启任何群/账号。
