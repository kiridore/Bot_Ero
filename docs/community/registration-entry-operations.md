# 注册入口修复的配置与验证

适用1.54.2及以后，修复未注册菜单标识与公开欢迎配置。代码升级不会自动修改已有config.yaml。

## 已部署实例需要核对

1. 若要求新好友收到注册欢迎，在`bot.allowed_plugins`和`bot.system_plugins`两份现有列表中分别补上`welcome`，不要替换或丢弃其他已配置项。若没有allowed_plugins键，则保持既有兼容设置；不要为了此修复无意创建一个只有welcome的名单。
2. 保留auto_friend负责同意申请、register负责主动注册；welcome不代替这两个插件。
3. 核对`bot.text_pack`指向部署使用的文案包，`welcome.friend_add`为既有好友欢迎文案；缺键继续使用内置文案。
4. 重启后验证菜单与欢迎。自定义部署可以不启用welcome，本次不会强制开启。

## 真实QQ试运行清单（需部署侧执行）

- 新账号发送好友申请，申请被同意；好友添加通知后只由welcome发送一条欢迎。
- 在没有注册的情况下发送/菜单和/菜單，看到注册及菜单入口，没有打卡等业务条目。
- 未注册发送/打卡，不执行打卡，只按既有规则限频提醒。
- 主动/注册后才开始协议流程；发送/同意EULA前不登记账号、不开启基础包。
- 已注册账号和超级用户的原有功能不退化；群审核和部署禁用继续生效。

“一次欢迎”指单次好友添加通知，不承诺上游重投通知去重。模拟事件测试不等于真实QQ送达验证；不将好友申请本身视为协议同意。
