# 微博首页抓取：Ubuntu 部署与验证

适用1.60.1及以后。消息源2号为明日方舟官方微博，1号FF14不变。

## 为什么需要浏览器

直接HTTP请求微博API在已测试的本机/部署环境返回432；普通未登录Chromium可正常完成访客页面流程并加载手机首页。正常滚动翻页会进入登录页，因此本功能只读首页，不登录、不翻页、不用反检测脚本、不导入已有Cookie。页面生成的临时访客会话随本轮浏览器关闭而销毁。

首页容量不固定（本机观测为12条含置顶，不是保证）。两次轮询间更新过多或长时间停机可能漏掉首页之外内容；48小时仍是推送年龄过滤，并不代表覆盖48小时全部消息。

## 安装（Ubuntu Server，无需桌面）

以下命令在项目根目录、机器人使用的虚拟环境内执行。需要网络下载Chromium和系统依赖，安装过程会占用数百MB磁盘。

1. **以运行bot的服务账户**登录，激活其虚拟环境。不要另建一个bot不会使用的环境。检查：

   ```bash
   whoami
   python -c 'import sys; print(sys.executable)'
   python -m pip install -r requirements.txt
   ```

   Playwright固定为1.64.1，与验证版本一致。Web应用不使用此依赖。

2. 安装Ubuntu系统库（需要管理员权限，官方命令可能提示sudo）：

   ```bash
   python -m playwright install-deps chromium
   ```

   如果bot服务账户没有sudo权限，请管理员使用这个虚拟环境的Python绝对路径执行同一命令；**这里只安装系统库**。

3. 回到bot服务账户，安装匹配的浏览器：

   ```bash
   python -m playwright install chromium
   ```

   浏览器通常位于该账户的 `~/.cache/ms-playwright/`。不要仅以root安装：root的缓存不是bot账户的缓存。systemd需保持正确的User/HOME并有权读取此目录；容器部署需在实际容器内安装依赖和浏览器，宿主机成功不能代替容器验证。

## 只读检查

在相同账户、环境与项目根目录执行：

```bash
python plugins/news/weibo_browser.py
```

该文件不加载config.yaml、不启动bot、不读写数据库、不发送QQ消息。它会创建一次全新浏览器上下文，正常打开手机主页，等待首批账号微博响应，验证后打印账号、条数及最多3条ID/完整时间，随后关闭浏览器。不要把HTTP200或单纯打开访客页当作成功。

- 成功：打印“微博首页读取成功”，退出码0。
- 失败：打印“微博首页检查失败”，退出码1。可用 `echo $?` 查看退出码。
- 若显示浏览器找不到：确认账户、Python环境及浏览器安装步骤一致。
- 若缺系统库：由管理员重新运行 `install-deps chromium`。
- 若HTTP432、登录页或超时：停止本轮验证并保留错误信息，不复制登录Cookie或绕过验证码。

本机Windows已实测此命令成功；Ubuntu服务器尚需实际运行。诊断不验证图片在OneBot端是否可达，也不验证QQ投递。

## 机器人运行验证

1. 安装完成并部署新版后重启bot（运行中不自动pip安装或下载浏览器）。
2. 群内 `/订阅` 确认2号源；`/订阅 2` 订阅。
3. 每整点、半点轮询。已有游标继续使用；没有游标时首次成功只记基线，不补历史。
4. 等待新微博后，检查默认群的AT、摘要、图片及原文链接；不主动向真实群发送测试消息。

依赖缺失或浏览器失败只会令微博源本轮失败、保留游标，不阻止FF14处理。浏览器每轮启动后关闭，不常驻、不共享跨线程对象；需要为进程启动、内存和网络请求预留资源。启动超时30秒，导航与内容响应等待各45秒。
