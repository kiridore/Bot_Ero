# 卧底观战与历史记录操作说明

## 玩家使用

- 出局后默认留房观战，收到描述汇总、各轮结果与最终揭晓；不能继续描述/投票。
- `/退出` 或 `/离开`：停止本局主动私聊，释放占用，可加入其他等待房间；已开局不能重新加入原局。
- `/游戏记录` 或 `/游戏记录 列表 [页码]`：私聊看本人参与，群聊看当前群；每页10条。
- `/游戏记录 查看 <记录编号>`：查看允许范围内的详情。编号以列表中的`#数字`为准，指令输入数字本身；不是4位房间号。
- 未开局离开、主动解散、正常结束与重启中断均留下记录。提前离开后仍可查询本局最终结果，不能私聊查询他人的未参与对局。
- 开局只得到自己的词条，不告知阵营；群公告可有双方人数。正常结束才公开身份和词条；观战、状态、进行中/解散/中断历史不提前揭晓。

## 战绩与投票

- 出局后观战仍正常计所属阵营胜负。
- 正式开局后主动退出，在本局正常结束时只计参赛，不计本局获胜及胜利称号；未开局退出不计参赛。
- 解散或重启中断不计完成战绩/奖励，不扣除过去的统计和称号。
- 退出者的选票及指向他的选票作废，需要时补投；本轮结果保留本轮刚被淘汰者，以后轮次不再列出他。
- 每局结束记录、统计和称号一次性同事务提交，发送失败不重复结算。

## 部署与数据

1. 本次在独立功能分支开发，合并/推送/部署另行授权；不要把开发分支的存在当成线上已生效。
2. 升级前等进行中的游戏结束，再停止bot并备份配置和SQLite数据库（使用SQLite备份方式，不在活跃写入时只复制主文件而漏掉WAL）。
3. 启动自动增加`spy_game_records`、`spy_game_participants`并确保原`user_game_stats`表存在；不改旧统计，不导入、不删除旧`server_data/game_records`文件。
4. 所有新状态使用配置的数据库路径，无新增独立数据库/服务。旧`/游戏记录 <房间号>`不兼容，提示改用新语法。
5. 新进程在接收事件前一次性将遗留未结束记录标记中断，不恢复游戏；正常WebSocket重连不做这一步。
6. 保存失败不确认成功；启动恢复失败停止启动，先排查磁盘、数据库权限与锁占用。发送失败日志标明业务已提交，不自动重试；可用记录编号核对结果。
7. 新记录未设置自动删除期限，随现有数据库备份；如以后要清理，另行确认保留规则，不能直接删除用户历史。

## 验证边界

自动回归使用隔离DB与QQ替身，不代表真实QQ送达已经验证。实际试运行应验证：开局隐藏阵营、出局后的完整观战、退出停止通知、群与私聊历史范围、分页及合并转发显示、断网后查询已结算结果。真实QQ联调不在自动实现过程中擅自进行。
